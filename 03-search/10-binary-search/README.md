# 10. Быстрый двоичный поиск (`BinarySearch`)

| Файл | Назначение |
|---|---|
| `binary_search.c` | две версии двоичного поиска и таблица трудоёмкости |

**Сборка:**

```bash
clang binary_search.c -o binary_search -lm && ./binary_search
```

## Задание

1. Для 12 первых символов ФИО выполнить вручную быстрый поиск двумя версиями для самой частой буквы.
2. Написать две версии двоичного поиска элемента в упорядоченном массиве; проверить на первом элементе, последнем и отсутствующем; считать `Сф`.
3. Сравнить трудоёмкость двух версий, построить таблицу для `N = 100 … 1000`.
4\*. Написать поиск всех элементов с заданным ключом (`BSearchAll1` и `BSearchAll2`) с подсчётом `Сф`.
5\*. Построить графики зависимости `Сф` от `n` для обеих версий.

## Псевдокод

**Версия 1** — два сравнения на итерацию, находит любой из равных элементов:

```
L ← 1,  R ← n
DO пока L ≤ R
    m ← ⌊(L+R)/2⌋
    IF aₘ = X THEN найден, выход
    IF aₘ < X THEN L ← m+1 ELSE R ← m−1 FI
OD
```

**Версия 2** — одно сравнение на итерацию, находит самый левый из равных:

```
L ← 1,  R ← n
DO пока L < R
    m ← ⌊(L+R)/2⌋
    IF aₘ < X THEN L ← m+1 ELSE R ← m FI
OD
найден ⇔ a_R = X
```

## Трудоёмкость

| Версия | Сравнений на итерацию | Итого |
|---|:---:|---|
| Версия 1 | 2 | `C ≤ 2·⌈log₂ n⌉` |
| Версия 2 | 1 | `C ≤ ⌈log₂ n⌉ + 1` |

Обе версии дают `C = O(log n)`; для сравнения, линейный поиск по неупорядоченному массиву стоит `O(n)`.

**Требование к данным: массив должен быть отсортирован** — это единственная «зависимость от упорядоченности» у поиска.

Все элементы с одинаковым ключом версия 2 находит просмотром вправо от найденного, версия 1 — просмотром в обе стороны.

## Проверка правильности

- Поиск первого элемента массива, последнего и заведомо отсутствующего.
- Фактическое число сравнений `Сф` сравнивается с оценкой `log₂ N`.
