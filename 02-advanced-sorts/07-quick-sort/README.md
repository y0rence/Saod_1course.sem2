## Задание

1. Для 12 первых символов ФИО выполнить сортировку методом Хоара вручную.
2. Написать первую версию QuickSort; проверить контрольной суммой и числом серий; считать `Мф` и `Сф`.
3. Исследовать трудоёмкость на убывающих, возрастающих и случайных массивах, составить таблицу для `N = 100 … 500`.
4\*. Сравнить две версии метода по глубине рекурсии (не путать глубину с количеством рекурсивных вызовов).
5\*. Построить в одной системе координат графики `Мф + Сф` для HeapSort, ShellSort и QuickSort.

## Псевдокод

**Версия 1** — сортировка части массива с границами `(L, R)`:

```
x ← a_L,  i ← L,  j ← R
DO пока i ≤ j
    DO пока aᵢ < x:  i ← i+1  OD
    DO пока aⱼ > x:  j ← j−1  OD
    IF i ≤ j THEN aᵢ ↔ aⱼ,  i ← i+1,  j ← j−1
OD
IF L < j THEN Сортировка(L, j)
IF i < R THEN Сортировка(i, R)
```

**Версия 2** — рекурсия только для меньшей части, большая обрабатывается циклом:

```
DO пока L < R
    <разделение, как в версии 1>
    IF j − L > R − i THEN Сортировка(i, R),  R ← j
                     ELSE Сортировка(L, j),  L ← i
OD
```

## Трудоёмкость

| Случай | Оценка |
|---|---|
| Худший: упорядоченный массив | `M = 3(n − 1)`, `C = (n² + 5n + 4)/2` → `O(n²)` |
| Лучший: ведущий элемент — медиана | `C = (n+1)·log(n+1) − (n+1)` |
| Средний | `C = O(n log n)`, `M = O(n log n)` |

**Глубина рекурсии:** у версии 1 на упорядоченном массиве достигает `n`, у версии 2 не превышает `log₂ n`. Каждый вызов занимает кадр стека (фрейм), поэтому для больших массивов важна именно версия 2.

**Зависимость от упорядоченности: сильная** — упорядоченный массив является худшим случаем.

**Устойчивость:** неустойчивая.

## Проверка правильности

- **Контрольная сумма.** Сумма элементов до и после сортировки должна совпадать: иначе элементы потерялись.
- **Число серий.** Серия — неубывающий участок. У массива, упорядоченного по возрастанию, ровно одна серия.
- **Счётчики `Мф` и `Сф`** сравниваются с теоретическими оценками на убывающем, случайном и возрастающем массивах.
